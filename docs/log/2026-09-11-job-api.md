# 2026-09-11 — Job API (`feat/job-api`, bounded context E)

Wave 0 of the production-hardening plan (`.claude/AGENTS.md`). The single-scene
Starlette server became an ingest/status service without changing what it served
before. Maintainer decisions honoured: uploads are PerceptionBundle or TUM
archives, never MP4; no separate frontend container (the committed `frontend/dist/`
is served by the same app).

## What is runnable now

```bash
python scripts/serve.py --scene out/scene_test                  # root viewer + job API, mock worker
python scripts/submit_job.py --bundle bundles/office_3 --tier 2  # zip, POST, poll to done, print /jobs/<id>/
python scripts/serve.py --scene S --worker-mode real             # pod only: spawns scripts/run_assemble.py
SOBA_PYTHON=.venv/bin/python NODE_PATH=~/tmp/pptr/node_modules \
  node scripts/verify_browser.js --scene out/jobs/<id>/scene --path /jobs/<id>/
pytest tests/api                                                 # 79 tests, no open3d / cv2
```

Routes, in registration order (first match wins):

| Method | Path | Notes |
|---|---|---|
| GET | `/`, `/scene.json`, `/eval.json`, `/meshes/{id}.glb`, `/hulls/{stem}.glb`, `/events` | legacy single-scene routes, byte-for-byte |
| POST | `/api/jobs` | multipart `archive` (zip / tar.gz / tar) + `tier` (1–4, default 2) → 202 job JSON |
| GET | `/api/jobs` | list, newest first |
| GET | `/api/jobs/{id}` | job JSON: `status` is `queued` / `running:<stage>` / `done` / `failed`, plus `history` |
| DELETE | `/api/jobs/{id}` | 204; removes the record and the whole job dir |
| GET | `/jobs/{id}` | 307 → `/jobs/{id}/` (the static catch-all mount pre-empts `redirect_slashes`) |
| GET | `/jobs/{id}/`, `/jobs/{id}/scene.json`, `/jobs/{id}/eval.json`, `/jobs/{id}/meshes/{id}.glb`, `/jobs/{id}/hulls/{stem}.glb`, `/jobs/{id}/events` | the same six handlers resolved through the job store |
| * | `/assets/...` | static mount of `frontend/dist/`, last |

Errors under `/api` and every job-scoped 404 use one envelope,
`{"error": {"code", "message"}}`; the legacy routes keep their plain-text bodies.
Upload rejections: 400 no `archive` field / malformed multipart, 413 over the
upload or extracted-size cap, 415 not an archive (MP4 lands here), 422 bad tier,
zip-slip, links, unknown layout, invalid manifest, or a TUM layout on a server
without an imaging backend.

## Design

- **`src/server.py` is a shim.** `api.app.create_app(scene_dir, frontend_dir, *,
  jobs_dir, worker_mode, fixture_scene, start_worker, max_upload_bytes, store,
  queue, worker_python)` composes three route groups; the two positional
  arguments are the whole legacy signature, and `_ID_RE` / `_HULL_RE` are
  re-exported, so `tests/test_server.py` and `scripts/serve.py` did not change.
  Later agents add a module under `src/api/` and one registration line in
  `app.py` (AGENTS.md shared-file rule).
- **One set of scene handlers, two prefixes.** `routes/scene.py` takes a
  `resolve(request) -> Path | Response` callable. The root app passes a constant;
  the job routes look the id up in the store and return the 404 envelope. This is
  why the legacy routes stay byte-for-byte: they are the same functions.
- **Validation at upload time, in a threadpool.** The archive is streamed to
  `out/jobs/<id>/upload.<ext>` with `aiofiles`, then
  `jobs/archive.py:validate_and_extract` sniffs the magic bytes (never the file
  name), extracts with the zip-slip guards (absolute paths, `..`, drive letters,
  backslashes, tar links/devices rejected; caps on expanded bytes and member
  count), detects the layout (bundle at the root or in a single top-level dir,
  `__MACOSX` ignored) and opens it with `PerceptionBundle.open`. A bad archive is
  therefore a synchronous 4xx and never a failed job. security-agent (phase B)
  extends this one function.
- **Store: memory + sqlite, one state machine.** `queued -> running(stage) ->
  done | failed`, `queued -> failed` allowed, terminal states frozen
  (`InvalidTransition`), every accepted transition appended to `history` so a
  client can see the path without polling fast enough. `SqliteJobStore` is stdlib
  `sqlite3`, WAL, a fresh connection per call under a lock, `BEGIN IMMEDIATE` on
  transitions — good enough for one API process plus one worker, and for a second
  process on the same host. The default store is opened lazily so importing
  `server` (for `uvicorn server:app`) does not create `out/jobs/`.
- **Queue contract for the orchestration agent.** `JobQueue.put(job_id) ->
  None`, `get(timeout: float | None = None) -> str | None`, `close() -> None`.
  Semantics: FIFO, each id delivered to exactly one `get()`, `None` on timeout or
  after close, `put` after close is a no-op, no ack/redelivery (a worker that dies
  leaves the job `running`; that is the retention policy's problem). Redis mapping:
  `put` = `LPUSH soba:jobs id`, `get` = `BRPOP soba:jobs timeout`, `close` = flag
  so blocked consumers return. The store is the source of truth; the queue only
  says "look at this id".
- **Worker.** `jobs/worker_local.py` is a daemon thread inside the API process
  (`SOBA_WORKER_INPROC=1`, so run ONE uvicorn worker), stages `validating ->
  (converting, TUM only) -> assembling`. `mock` copies a fixture scene
  (`SOBA_FIXTURE_SCENE`, else `out/scene_test`) or writes a schema-validated empty
  scene; `real` / `gate-only` spawn `scripts/run_assemble.py --no-eval` with the
  log in `out/jobs/<id>/worker.log`. Because the in-process queue is not persisted,
  the lifespan re-enqueues jobs still `queued` in the store at startup.
- **Job-scoped SSE.** `/jobs/{id}/events` replays `object_added` like the root
  route and, while the job is not terminal, polls the store every 0.5 s: emits
  `job_status` on each change and announces objects as the worker writes them.
  The viewer ignores event names it does not know, so nothing changed there.
- **Frontend (the one context-D touch).** `sceneUrl()` in
  `frontend/src/viewer/loaders.ts` prefixes scene paths with `/jobs/<id>` taken
  from `window.location.pathname`; the four call sites in `SobaViewer.ts` and the
  `eval.json` fetch in `EvalReportPanel.tsx` are one-token edits. Bundle assets
  are absolute (`/assets/...`) so no Vite `base`; the dev proxy forwards `/api`
  and `/jobs`. `dist/` rebuilt and committed.

## Follow-ups

No retention policy (STATUS.md). Auth, rate limits and upload MIME policy are
security-agent phase B. `/metrics` and request logging are observability phase B.
Multi-process API deployments need the Redis queue (orchestration agent) and
`SOBA_WORKER_INPROC=0`.
