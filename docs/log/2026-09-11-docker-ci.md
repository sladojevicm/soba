## Decisions

- **Ruff baseline = E9 + F only.** With no config ruff reported 127 findings, most
  style rules in files other Wave-0 agents are editing. Pyflakes-only keeps the
  lint job meaningful (undefined names, unused imports) without a formatting
  sweep that would conflict. The 14 findings were cleared; one `F821` in
  `slam.py` is a false positive (closure over the enclosing function's `out`)
  and is `noqa`'d with a comment.
- **API image = editable install + `PYTHONPATH=/app/src`.** `server.py` is a
  top-level module (not found by `packages.find`) and locates `frontend/dist`
  relative to its own file, so a non-editable install would lose both. Non-root
  uid 10001, `HEALTHCHECK` on `/scene.json` with the stdlib (slim has no curl);
  `/scene.json` answers 200 before a scene is mounted, so the health probe is
  independent of data. `SOBA_EXTRAS` build arg flips to `serve,api` when the
  job API lands. No frontend container (maintainer decision 2).
- **Pipeline image base = `pytorch/pytorch:2.6.0-cuda12.4-cudnn9-runtime`**, the
  torch/CUDA the 4060 ran (`docs/log/2026-06-28`) and what `bootstrap.sh` assumes
  a RunPod PyTorch template provides. `coacd` and `runpod` are installed
  explicitly because no extra provides them — **`coacd` is missing from the
  `recon` extra although every hull collider in `BENCHMARK.md` depends on it**
  (finding for the maintainer; not changed here). The Open3D CUDA check warns at
  build time and is re-runnable as `docker run --gpus all soba-pipeline check`.
  The `-devel` base is documented for the serverless variant (TripoSG `diso`,
  hy3dshape need nvcc).
- **frontend-check** builds with `npm ci` into a separate outDir and `diff -r`s
  against the committed `frontend/dist`; any byte difference fails the job.
- **Compose**: `api` alone by default; `cpu` profile adds redis + a placeholder
  worker (real command arrives with the orchestration work); `gpu` profile runs
  the pipeline image with the NVIDIA runtime. `make loadtest` exits 2 until the
  load-test work lands.

## Model-pin audit (`docs/model-pins.md`)

Nothing in the repo pins a git commit, checkpoint sha256 or HF revision for
YOLO, SAM2, MASt3R, TripoSG, Hunyuan3D 2.1, PatchComplete, PoinTr or ComPC:
all clones are `--depth 1` of the default branch, all HF downloads take `main`.
Only filenames, HF ids, run parameters (steps/cfg/seed/face caps) and the
library versions in the `BENCHMARK.md` header are recorded. The recovery
commands (to run on the 4060 and, if it still exists, the pod volume) are in
`docs/model-pins.md`.

**Finding from the pipeline build log.** The Open3D CUDA check did not fail
for lack of a GPU: the wheel pip resolved from PyPI says
`Unsupported device "CUDA:0". Set BUILD_CUDA_MODULE=ON to compile for CUDA
support`, i.e. **that `open3d==0.19.0` wheel has no CUDA module**, so TSDF in
this image would run on CPU even on a GPU host. Whether the pod's
`bootstrap.sh` (same `pip install`) ends up with a CUDA-capable wheel cannot be
verified from this box; `docs/log/2026-06-28` records "open3d 0.19 CPU build"
on the 4060 as well. Recommended check on a GPU host:
`docker run --rm --gpus all soba-pipeline check` — it exits 1 if the CUDA tensor
backend is missing. Not fixed here (which Open3D wheel/index provides CUDA for
this torch/CUDA combination is a maintainer decision, not a guess to bake in).
